How we publish technical work without inventing results.

Maintainer: Satzzxzxx Labs project repository. Published 28 October 2026. This article describes publicly inspectable implementation choices for this website; it does not claim outside certification or traffic outcomes.

Start with an inspectable repository

Our website source is publicly visible on GitHub. The pages are plain HTML, CSS and a small JavaScript navigation helper, hosted at the project's GitHub Pages address. Keeping content static makes the page readable without JavaScript-based data retrieval, and reduces the need for a runtime application server for these pages.

Use one brand, but preserve accurate attribution

Our portfolio links to FinCo-Pilot, OpenXdrive and UNILOOP. That does not mean the original repositories all share one GitHub owner. For example, the public organization UNILOOP repository is marked as a fork; its upstream is meshishu/UNILOOP. We link to both rather than erasing the upstream relationship.

Separate experiments from publishable claims

A repository or feature route is evidence that code exists, not proof that every product flow has passed a live user test. A draft is not a finished article. Future posts will distinguish implementation evidence, deploy evidence, third-party observations and the author's interpretation. Editorial review is especially important for security allegations and financial software comparisons.

Make release checks repeatable

We keep a public route and project catalog, a sitemap of eligible pages, and a static verification script that checks local links, titles, canonicals and publication status. The repository's GitHub Actions workflow runs these checks on proposed changes. Publishing still requires an appropriate approved source and successful deployment; CI status alone does not prove the page is live.

Where to read the approach

Review the architecture notes, editorial policy and official GitHub Pages publishing guidance. These documents reflect the intended process; actual Actions and public Pages deployment must be checked after every merge.
